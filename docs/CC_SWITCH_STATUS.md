# CC Switch 远端状态接入

## 目标

当前 App 的远端状态不应假定 Codex 使用 OpenAI 官方账号。服务器由 CC Switch 接管供应商时，优先显示 CC Switch 实际返回的供应商和额度数据。输入栏圆圈会直接显示有效余额的整数部分，完整数值仍保留在远端状态弹窗。

## 已核实环境

1. 服务器：隔离的测试环境。
2. CC Switch：`5.11.3`。
3. 当前应用类型：`codex`。
4. 当前供应商：`deepseek`。
5. 额度命令返回：可用状态、供应商、余额、单位和查询时间等字段。

## 调用流程

1. App 使用已经建立的 SSH 连接启动辅助会话。
2. 执行 `cc-switch -a codex provider list`。
3. 从 `→ Current: <id>` 或带选中标记的表格行识别当前供应商。
4. 校验供应商 ID 只包含字母、数字、点、下划线和短横线。
5. 执行 `cc-switch -a codex provider quota <id> --json`。
6. 解析顶层状态、供应商名称、查询时间、额度和错误。
7. 在“远端状态”弹窗显示数据源 `CC Switch`。
8. 在输入栏圆圈内显示第一条有效余额的整数部分，不显示货币符号、小数和单位。
9. 没有有效余额时不显示推测值。连接成功和每轮任务结束后自动刷新。

## 回退规则

1. 命令返回 `127` 或找不到 `cc-switch` 时，回退到 Codex `account/rateLimits/read`。
2. CC Switch 可运行但额度脚本失败时，显示 CC Switch 的错误，不触发 Codex 官方额度查询。
3. 辅助 SSH 命令本身失败时，显示“CC Switch 状态读取失败”，不显示“SSH 认证失败”。

## 安全边界

1. 不使用 `provider current`，因为它在当前版本会输出 API Key。
2. 不读取 CC Switch 配置文件。
3. 不执行 `provider switch`、`usage-query`、`quota --reset` 等变更命令。
4. 供应商 ID 经过白名单校验后才拼入命令。
5. 单元测试固定 `provider current` 不会被调用。

## 测试覆盖

1. 真实服务器只读命令确认了 CC Switch 版本、当前供应商和 DeepSeek 额度 JSON。
2. 单元测试覆盖供应商列表解析、ANSI 清理、JSON 额度解析、未安装回退和额度脚本失败。
3. 设备测试在 API 35 模拟器上确认弹窗显示 `CC Switch`、供应商、余额和单位，并确认不出现 SSH 认证误报。
4. 设备测试确认圆圈只显示余额整数，不显示货币符号、小数或单位；同时验证圆圈可点击、上下文描述仍保留、`1.3` 倍字体和 `320dp` 宽度下不越界。

## 未验证范围

1. 尚未在一台保存了真实 SSH 凭据的真实 Android 手机上完成从连网到 CC Switch 状态弹窗的整条端到端黑盒；目前分别验证了真实服务器 CLI 数据和 App 设备界面。
2. CC Switch 其他版本的输出格式可能变化；本版只对 `5.11.3` 的真实输出完成验证。
